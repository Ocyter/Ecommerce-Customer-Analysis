HOW THE CHECKS WORK

Keep the source.
Explain every exclusion.

Raw records stay unchanged. Each order receives one primary quality issue or passes validation, then a separate reporting rule selects completed orders.

  1. Check the keys. Count repeated order IDs and customer IDs. Quarantine ambiguous keys instead of picking a record without evidence.
  2. Control the join. Summarise customer keys before joining orders, so a duplicate customer cannot silently multiply the fact rows.
  3. Check completeness and amounts. Flag unknown customers, missing regions, missing amounts and negative amounts.
  4. Separate quality from scope. Pending and cancelled orders can be valid records while remaining outside the completed-order report.
  5. Reconcile and verify. Assert expected rejected rows, regional totals, row conservation and known-amount conservation.

The fixture exercises six primary defect types. Missing-ID and invalid-status guards are present but not seeded. One primary rejection reason is logged per row.
